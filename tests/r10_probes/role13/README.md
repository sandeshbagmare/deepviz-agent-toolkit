## What RED and GREEN mean here

- Scratch schema generated by the real exporter first passes `--check`. A
  valid-JSON nested contract change then returns **1**, and its bytes stay stale;
  the gate must not silently repair them. Only scratch files are changed.
- Actual `evidence-required` label plus incomplete or unsafe-link packet returns
  **1**. The same gate's complete synthetic-format control returns **0** but
  explicitly disclaims report truth, independence and approval.
- Merely writing `evidence-required` inside PR body does not set the label. The
  absent-label bootstrap path returns **0** with an explicit nonapproval warning.
  Never count that green result as the required-evidence gate passing.
- Untrusted command-looking body text stays inert; no shell is invoked.
- A real child pytest run has one deliberate assertion failure, one pass,
  exit **1** and JUnit with exactly one failure/no setup errors. Its positive
  control returns **0**. The outer test is GREEN only when those RED child exits
  are observed correctly; this is not a production-source RED→GREEN fix claim.

No URL/report is fetched, and structural format acceptance does not prove URL
safety/content truth or authenticate four independent reviewers/testers. These
local CLI checks do not establish Linux/Node24/remote Actions acceptance.
