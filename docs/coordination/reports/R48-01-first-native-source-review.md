### Must fix: finite extreme line crashes the Matplotlib native path

**Where:** `python/deepviz/src/deepviz/engines.py:253-285,365-371`; public call `render.py:177-187`.

**Reproduction:** two literal records `[{'t': 0, 'v': -1e308}, {'t': 1, 'v': 1e308}]`; `ChartSpec(kind='line', x='t', y='v', aggregation='none', width=640, height=400)`; engine `matplotlib`. The same isolated probe first ran ordinary `[-1.0, 1.0]`, then this one finite-extrema case. It loaded the exact Git source under `python -B -I -S`, with existing readonly Matplotlib 3.11.2, NumPy 2.5.5, Pydantic 2.14.4 and only child-owned cache/temp paths.

**Observed:** ordinary control passed with 2 input/2 output records, strategy `none`, PNG/SVG/HTML/manifest, finite native points and unchanged caller rows. The finite-extrema case failed with `ValueError: arange: cannot compute length` after the native line was created. Trace: `render.py:178` -> `engines.py:366` `axis.get_ticklabels()` -> Matplotlib `ticker.py:2307`/`2290`. Matplotlib emitted `overflow encountered in scalar subtract`. The retained native y data is exactly `[-1e308, 1e308]`; caller sentinel/data stayed unchanged. The failed output subtree contains only the caller sentinel and an empty renderer directory, with no completed artifact.

**Why real:** both values are finite and survive `_number`/normalization, but axis tick formatting crashes instead of returning a bounded artifact or a clear supported-input error. This is distinct from the underscore legend, COUNT, normalizer, browser, AntV and Plotly findings.

**Fix direction:** producer18/R04 should either apply an explicit finite-axis policy that rejects unsupported extremes with a clear error before artifact allocation, or use a bounded axis/formatting strategy that preserves finite values without backend overflow. Do not silently clamp, replace values with null, or alter shared normalization. **Impact if skipped:** a finite input can fail with a backend `ValueError`; first-native support cannot honestly claim the full finite numeric range.
